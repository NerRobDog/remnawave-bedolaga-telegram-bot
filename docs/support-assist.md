# Ассистент поддержки

Что делает: на каждый новый тикет и на каждый ответ клиента отправляет владельцу в админский топик тикетов
карточку разбора. Карточка строится из детерминированных проверок (снимок аккаунта, подписки и панели, флаги
без LLM); Claude связывает факты, называет вероятную причину и пишет черновик ответа. Если ключа нет или
модель недоступна, карточка рисуется из одних флагов. Ассистент ничего не пишет в данные клиента: только
подсказывает владельцу.

Спецификация: `docs/superpowers/specs/2026-11-06-support-assistant-design.md`.

## Настройки (env бота)

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `SUPPORT_ASSIST_ENABLED` | `false` | Главный выключатель: карточки в админский топик. |
| `SUPPORT_ASSIST_AUTO_ASK_ENABLED` | `false` | Автовопрос клиенту на голое первое сообщение (фиксированный набор вопросов, один раз на тикет). |
| `SUPPORT_ASSIST_SEND_BUTTONS_ENABLED` | `false` | Кнопки владельца «Отправить / Править / Пропустить» под карточкой. |
| `ANTHROPIC_API_KEY` | пусто | Ключ Anthropic API. Пусто: карточки без модели. |
| `SUPPORT_ASSIST_MODEL` | `claude-opus-5-5` | Модель карточки. |
| `SUPPORT_ASSIST_TIMEOUT_SECONDS` | `90` | Таймаут запроса к модели. Весь вызов (с повторной попыткой SDK, `max_retries=1`) дополнительно ограничен этим значением плюс 10 с: по истечении рисуется карточка без модели, слот конвейера свободен. |
| `SUPPORT_ASSIST_EFFORT` | `medium` | Глубина размышления модели: `low`, `medium`, `high`, `xhigh`, `max`. Неизвестное значение читается как `medium`. |
| `SUPPORT_ASSIST_FALLBACKS_ENABLED` | `true` | Серверный запасной ход: при отказе классификаторов API повторяет запрос на другой модели в том же вызове. Выключить: запрос уходит без заголовка бета и без `fallbacks`. |
| `SUPPORT_ASSIST_RECOMPUTE_MINUTES` | `10` | Не чаще одного разбора на тикет за это окно. |
| `SUPPORT_TICKET_FORM_REQUIRED` | `false` | Обязательная анкета перед тикетом в боте и кабинете (см. ниже). |

Карточка (вызов модели и сообщение в топик) идёт только при включённых админ-уведомлениях и заданном чате.
Автовопрос клиенту от них не зависит: у него свой флаг, он работает и при выключенных админ-уведомлениях (строка
карточки получает статус `skipped`, модель не вызывается, в топик ничего не уходит).

## Кнопки карточки

- «Отправить» шлёт клиенту черновик как есть, поэтому работает только для черновика, который поместился в
  сообщение карточки целиком (лимит Telegram 4096 знаков). Если черновик урезан, под карточкой строка «Черновик
  слишком длинный…», кнопки «Отправить» нет, остаются «Править» и «Пропустить». Обработчик отдельно отказывает
  (всплывающее окно), если сохранённый черновик в карточку целиком не влез или карточку не удалось собрать заново.
- «Править» присылает админу в личку черновик и ждёт его текст. Запрос действует 30 минут: позже текст не уходит,
  состояние снимается, админу сообщают, что время вышло, карточка остаётся нетронутой. Текст, начинающийся с «/»,
  клиенту не отправляется никогда: админу предлагают прислать обычный текст, запрос остаётся.

## Три фазы выката

1. Тень: `SUPPORT_ASSIST_ENABLED=true`, остальные флаги выключены. Карточки приходят владельцу, кнопки скрыты, клиенту ничего не уходит. 1-2 недели, замер стоимости и полезности.
2. Кнопки: `SUPPORT_ASSIST_SEND_BUTTONS_ENABLED=true`. Владелец отправляет клиенту черновик (или свой текст) кнопкой.
3. Автовопросы: `SUPPORT_ASSIST_AUTO_ASK_ENABLED=true`.

Каждая фаза выкатывается по скиллу `bedolaga-prod-update` (бэкап, dry-run миграции, откат) и только после
«да» владельца. Откат любой фазы: выключить соответствующий флаг и перезапустить бот.

## Анкета перед тикетом

`SUPPORT_TICKET_FORM_REQUIRED` (по умолчанию `false`) делает короткую анкету обязательной: платформа,
приложение, сеть, что не работает, с какого момента. Ответы кнопками (свободный текст до 100 знаков только
в «Другое») лежат в `tickets.diagnostics` как id вариантов, видны владельцу в уведомлении о новом тикете и
уходят ассистенту фактами. Автовопросы не спрашивают то, на что анкета ответила.

- Бот: пять шагов с inline-кнопками (`tf:<поле>:<вариант>`) перед запросом заголовка. Флаг выключен: поток прежний.
- Кабинет: `POST /cabinet/tickets` принимает `diagnostics`. Флаг включён, анкеты нет или она неполная: 422, тикет не
  создаётся. Флаг выключен: годная анкета сохраняется, отсутствующая или битая не мешает. Выбрано «Другое» (платформа,
  приложение), а текста нет или он из одних пробелов: анкета негодная, как и в боте.
- Флаг для кабинета: `GET /cabinet/info/support-config` отдаёт `ticket_form_required` (значение
  `SUPPORT_TICKET_FORM_REQUIRED`). Кабинет с формой учитывает это поле и показывает анкету только при `true`.
  Старый кабинет без формы поля не читает и анкету не присылает: при включённом флаге он получает 422.
- Тексты вариантов: ключи `TICKET_FORM_*` в локалях. Владелец утверждает их до включения флага; ru и en
  основные, ua, fa и zh переведены без вычитки.
- Порядок включения: сначала выкат кабинета с формой (старый кабинет без анкеты получит 422), потом флаг.
  Откат: выключить флаг и перезапустить бот; колонка `diagnostics` остаётся, миграция 0143 обратима.

## Порядок ответа админа в боте

Ручной ответ админа в тикете (`handle_admin_ticket_reply`) и кнопки карточки ассистента идут через общую
`send_admin_reply`: сначала сообщение сохраняется, затем клиенту уходит уведомление, и только после этого админу
приходит подтверждение «Ответ отправлен». Раньше подтверждение шло первым, клиента уведомляли в самом конце. Сбой
доставки клиенту подтверждение не блокирует (уведомление глотает свои ошибки), но порядок в журнале и во времени
теперь другой.

Автовопрос ассистента хранится как ответ админа с `is_system=true`. В админском просмотре тикета в боте он подписан
«🤖 автовопрос», в админском API кабинета и во внешнем webapi сообщение несёт поле `is_system`.

## Приватность

В API уходит только копия снимка по белому списку полей (`payload.py`); id, telegram_id, имена, e-mail, IP,
ссылки подписки, uuid, суммы и реквизиты платежей не копируются. Текст клиента уходит как есть. Причина
ограничения аккаунта (`restriction_reason`, свободный текст админа) не уходит: в нагрузке только виды запретов
(`subscription`, `topup`). Из анкеты
идут только id вариантов и короткий текст «Другое».
Клиенту уходят только фиксированные вопросы либо текст, который владелец сам отправил кнопкой.

## Стоимость

Каждый вызов записывает токены и цену в таблицу карточек (`input_tokens`, `output_tokens`,
`cache_read_tokens`, `cost_usd`). Цена считается по модели, которая реально ответила (`response.model`), по
таблице `PRICES` в `card.py` (Opus 5.5, $ за 1M токенов: вход 4, выход 20, чтение кэша 0.20, запись кэша 5; для
запасных моделей свои строки). Ответила модель, которой в таблице нет, а не настроенная в
`SUPPORT_ASSIST_MODEL`: берётся тариф настроенной, в журнал уходит `support_assist.cost_estimated`, а сумма —
оценка, не счёт. База знаний идёт кэшируемым блоком. Реальную цену карточки на проде ещё не измеряли:
её даст фаза 1 (сумма `cost_usd` по таблице карточек) или ручной прогон ниже.

## Ручной прогон оценки

Скрипт `scripts/support_assist_eval.py` прогоняет `generate_card` на синтетических сценариях S01-S15
(`tests/services/support_assist/fixtures.py`, сообщение клиента «Не работает впн») и, по желанию, на своих
кейсах. Он делает реальные вызовы Anthropic API и тратит деньги, поэтому без `--yes-spend` отказывается
запускаться. Нужны `ANTHROPIC_API_KEY` и остальные обязательные переменные окружения (как для бота).

```bash
uv run python scripts/support_assist_eval.py --yes-spend --out /tmp/support-eval
uv run python scripts/support_assist_eval.py --yes-spend --out /tmp/support-eval --cases my_cases/
```

Свой кейс: файл `*.md`; первая строка `# заголовок` необязательна, остальное — сообщения клиента, несколько
сообщений разделяются строкой `---`. Снимок для такого кейса: здоровый клиент без флагов.

В `--out` пишутся `<кейс>.json` (карточка, сообщения, токены, цена, ошибка) и `usage.csv` (токены и цена по
кейсам). Итоговая сумма печатается в конце. Оценку карточек (причина, вопросы клиенту, действие владельца,
черновик, по шкале 0-2) делает человек, как в spike.
